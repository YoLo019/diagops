# DiagOps V8.1 Reliability And Provider Compatibility Implementation Plan

> **Execution workflow:** Use `iteration-flow` Full mode. Execute the three milestones below in order. Use subagents only for independent work with non-overlapping files/contracts or for the two milestone reviews. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the V7 live-reliability gaps, persist safe structured execution diagnostics, produce schema-v3 reliability artifacts, and run the same multi-agent RCA runtime with explicit OpenAI or DeepSeek model Providers.

**Architecture:** Preserve deterministic RCA and the existing OpenAI Agents SDK orchestration as the authority boundary. First align hybrid agreement and safe execution contracts, persist them through SQLite/API/UI, and pass the unchanged V7 OpenAI gate; only then add one narrow DeepSeek Chat Completions adapter with strict local Pydantic validation and independent Provider certification.

**Tech Stack:** Python 3.12, FastAPI, Pydantic, SQLAlchemy/SQLite, OpenAI Agents SDK, OpenAI Python client, pytest, Ruff, React/TypeScript, Vite.

---

## Execution Rules

1. Work in an isolated `codex/` branch or worktree created at execution time.
2. Do not request, print, store, or commit an API key.
3. Complete Tasks 1-5 and pass the canonical OpenAI V7 gate before starting Task 6.
4. Apply one live-diagnostic fix at a time. If Task 5 reveals a new prompt, mapping, timeout, or arbitration defect not already authorized by the V8.1 spec, stop and write a focused spec amendment before changing behavior.
5. Do not lower reliability thresholds, relax evidence validation, repair malformed JSON, enable automatic Provider fallback, or add production mutation tools.
6. Commit steps are execution instructions only; do not commit unless the user authorizes git actions for the execution session.
7. At execution start, update `docs/superpowers/current.md` to `Iteration status: implementing` and `Implementation status: in_progress` before changing implementation files.
8. When a stop condition blocks further execution, update `current.md` to `Iteration status: blocked`, `Implementation status: blocked`, and record a concise non-`none` `Blocker`.
9. Immediately before final verification, update `current.md` to `Iteration status: verifying` and `Implementation status: verifying`.
10. Mark the iteration `complete` only after all required checks pass and an authorized completion commit exists. Record that commit and concise verification evidence in `current.md`. Without commit authorization, leave the iteration in `verifying` and report the pending finish action.

## Milestones And Review Gates

### Milestone 1: Reliability baseline and OpenAI stabilization

Execute Tasks 1-5. Then run one milestone review with `AGENT.md`, the relevant V8.1 spec and plan sections, the complete Milestone 1 diff, the focused test results, and the canonical OpenAI gate artifact summary. Review spec coverage, persisted-data compatibility, failure visibility, evidence integrity, safety boundaries, and whether Task 5 permits Provider compatibility to begin. Do not start Task 6 until blocking findings are resolved and the Task 5 stop gate passes.

### Milestone 2: Provider compatibility and deterministic verification

Execute Tasks 6-9. Then run one milestone review with the same required context plus the complete Milestone 2 diff and current full verification results. Review the serialized DeepSeek request contract, strict local output validation, missing-credential attribution, Provider isolation, certification semantics, secret handling, deterministic fallback, and absence of a second Agent runtime. Do not start paid Provider certification until blocking findings are resolved.

### Milestone 3: Independent certification and finish

Execute Task 10. This milestone uses the final review and verification in Task 10 rather than dispatching an additional reviewer. Record skipped live checks and residual risk explicitly; a Provider may be `not_run` only where the approved spec permits it.
