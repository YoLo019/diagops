# DiagOps V10.1 Signal Ranking Reliability Design

状态：`approved`

日期：2026-08-01

## 1. Context and decision

V10 已证明生产七场景 Gate 7/7、Evidence 引用 100%、只读违规 0、零答案
泄漏，但 OpenRCA frozen six-case 仅 2/6 有 partial score，strict accuracy 为
0，time score 为 0。失败链已由冻结 Runtime Evidence 定位：OpenRCA 累计
counter 作为 gauge 输入；零基线且 MAD=0 的单点 blip 被封顶为 strength 10；
同分 attribution 再按最早 onset 排序，导致窗口起点噪声压过已检测到的真实
故障信号。

本迭代选择用户批准的方案 A：在现有 OpenRCA adapter、Signal Core、balanced
selection 和 Attribution 内做最小语义修复，不新建评分框架或可调参数层。同时
执行一次预注册 40-case 盲测；只有盲测达到本 spec 的 paired Gate，才可声明
OpenRCA 诊断质量提升。

工作流级别为 Full。原因是变更影响共享信号合同、持久化 Evidence payload、
历史 Replay、OpenRCA 排名和生产 Gate，且盲测一旦评分即不可逆地暴露 holdout。

## 6. Scope and non-goals

### 6.1 In scope

1. 冻结一个排除全部既有 40 case 的新 40-case holdout，每 partition 10，固定
   seed，保留 manifest、runtime index 和 SHA-256。
2. 在 V10 clean source identity 上先生成 holdout baseline predictions，评分延迟
   到 candidate predictions 冻结之后。
3. OpenRCA counter-like series 的保守 rate 转换。
4. 零基线/MAD=0 时的 presence-only strength 语义。
5. 把 segment 支持点数投影到 Evidence，并用于同分裁决。
6. 历史 payload、Replay、API、报告、生产 Prometheus 和七场景 Gate 兼容。
7. 一次性 paired evaluation、可复现 comparison artifact 和明确 stop rule。

### 6.2 Non-goals

1. 不使用 case ID、task、instruction、record Ground Truth 或评分结果选择规则。
2. 不重新评分或调参已暴露 six-case；它只保留为历史失败证据。
3. 不引入 ML、学习排序、权重配置、feature store 或新依赖。
4. 不改变 signal taxonomy、cause taxonomy、Projector、Runtime 状态机、数据库
   schema、公共 API shape 或前端。
5. 不为 counter reset 猜测语义；缺少可靠 metadata 时保留原 gauge 路径。
6. 不把 production Gate 7/7 表述为现实世界 100% 准确率。

## 7. Architecture and data flow

```text
OpenRCA raw metric series
  -> conservative counter-like detection and rate normalization
  -> existing Signal Core anomaly segmentation
     -> relative strength for usable baseline scale
     -> presence-only strength for zero/MAD=0 baseline
  -> additive Evidence quality fields
  -> existing family-balanced bounded selection with support tie-break
  -> existing Analyzer and segment-aware Attribution with support tie-break
  -> thin Projector (unchanged)

Prometheus query_range (already rate-normalized where required)
  -> same Signal Core and downstream ordering

Frozen unseen safe-index
  -> V10 baseline predictions (unscored)
  -> V10.1 candidate predictions (unscored)
  -> one official evaluation of both
  -> paired Gate and immutable comparison artifact
```

模块职责不新增层：OpenRCA adapter 只处理 vendor/raw series；Signal Core 只处理
纯数值语义；Attribution 只从 Evidence 生成根因排序；evaluator 只评分和校验。

## 8. Signal contracts and algorithms

### 8.1 Conservative counter-like conversion

对每个 `(component, instance, metric_name)` 合并 baseline 和 observation 后按
timestamp 排序。仅当以下条件全部满足时转换：

1. metric name casefold 后符合明确累计命名：以 `total_` 开头，或以 `_total`、
   `_count`、`_counter` 结尾；
2. 至少三个有限点且相邻时间严格递增；
3. value 单调不减；
4. 至少两个相邻 delta 严格大于 0。

每个转换点使用右侧样本 timestamp，value 为
`(right.value - left.value) / elapsed_seconds`。随后按原 `start/end` 边界重新分为
baseline 和 observation，再调用 Signal Core。负 delta、重复/倒序时间、样本不足
或不满足单调条件时不转换，完整保留现有 gauge 行为。

这是故意保守的 name + shape heuristic，不声称识别所有 counter。代码必须增加
`ponytail:` 注释记录 ceiling：有可靠 metric-type metadata 后替换 heuristic。

### 8.2 Degenerate baseline strength

当 baseline 有有限值且 `abs(median) <= epsilon`、`MAD <= epsilon` 时，baseline 没有可用于跨
series 比较的幅度尺度：

- 非零 observation 仍形成 segment，不删除 Evidence；
- `strength_basis = "presence_only"`；
- `strength = 1.0`，表示仅确认越过异常边界，不伪造幅度置信度；
- `anomaly_point_count` 为 segment 内有限异常点数。

其他 baseline 保持 V10 的 `max(3*MAD, abs(median)*0.1, epsilon)` 与
`min(deviation, 10)`，`strength_basis = "relative"`。baseline 为空或没有有限值
仍返回空；NaN/Infinity 不进入计算。

`strength_basis` 仅允许 `relative` 或 `presence_only`；
`anomaly_point_count` 必须为正整数。两个字段同时由 OpenRCA 和 Prometheus
segment Evidence 投影。

### 8.3 Balanced selection and Attribution

保持 family-first round-robin、limit 和去重 key，但禁止把 `presence_only=1`
当作可与 relative strength 比较的幅度。每个 family 按 derived basis 建立队列：

1. `relative` 队列内部沿用 strength 降序，再按 point count 降序和旧确定性字段；
2. `presence_only` 队列内部按 point count 降序，再按旧确定性字段；
3. `legacy` 队列内部完整沿用 V10 `_sort_key`；
4. 不同 basis 队列竞争时，只比较队首 point count，再按 onset、component、signal
   name、Evidence ID；绝不比较不同 basis 的 numeric strength。

Attribution 对 cluster 派生 basis：全部 relative 为 `relative`，全部缺字段为
`legacy`，其他为 `presence_or_mixed`。每个 basis cohort 内：relative 沿用现有
cluster score，legacy 沿用 V10 排名，presence/mixed 按总 point count、独立
Evidence 数、provider 数和 signal-type 数排序。不同 cohort 竞争时，只比较上述
共同 support tuple，再使用 onset/component/reason；不比较跨 basis strength。

持久化 `strength_basis` 仍只允许 `relative|presence_only`。历史字段缺失时由读取
accessor 派生内存态 `legacy`，不得把 `legacy` 写回 payload。历史
`anomaly_point_count` 缺失时内存默认 `1`；全历史 cohort 因而保持 V10 排名。

## 9. Blind paired evaluation contract

### 9.1 Holdout selection

`prepare` 增加 repeatable `--exclude-safe-index PATH`。每个文件必须通过现有
`OpenRcaRuntimeIndex(extra=forbid)` 校验；所有 `case_id` 合并成 exclusion set，
在 stratified sampling 前移除。排除后任一 partition 少于 `per_partition` 必须
显式失败。

V10.1 固定：每 partition 10、共 40、seed `101`，排除现有 V10 deterministic
40-case safe-index。holdout selection 由独立 custodian（用户或单独的只读任务）
在算法实现前执行；实施方只接收 runtime safe-index、case ID/hash 清单和不含
`record.csv` 的 runtime telemetry root。现有 prepare 内部可读取 `record.csv` 做
分层抽样，但输出不得含 component/reason strata 或 Ground Truth。

Custodian 必须记录 prepare source SHA、clean/dirty 状态、命令、输入 dataset hash、
exclusion index hash、输出 manifest/runtime-index hash 和 `40 selected / 0 overlap`；
不得输出所选 record 内容。该隔离是可审计的流程边界，不声称具备密码学访问隔离；
若 custodian 或实施方查看了所选 Ground Truth，holdout 立即作废并重新选择。

### 9.2 Paired execution order

1. 在 clean V10 source `7b26024` 的隔离工作区运行 deterministic fixed baseline；
   把原 run directory 作为 immutable execution bundle，记录 manifest SHA 和所有
   已列 artifact checksum，不运行 `evaluate`。
2. 执行并验证 V10.1；在 clean candidate source 上对同一 safe-index 运行一次；
   以相同方式封存 candidate execution bundle。
3. 分别复制两个 execution bundle 到独立 evaluation directory。复制后先验证
   manifest SHA、fixed predictions SHA 和 case set 与原 bundle 完全一致。
4. 只在 evaluation copies 上运行现有 compatible `evaluate`、生成 official query
   inputs，并用同一 clean official evaluator source 生成 official reports。允许
   evaluation copy 更新 summary/manifest；原 execution bundle 永不再写。
5. paired Gate 同时读取两个 immutable execution bundles 和两个 evaluation copies，
   验证 source/manifest/prediction/evaluator identity 后再比较。评分首次产生时
   holdout 永久转为 exposed。

### 9.3 Paired Gate

新增独立命令，避免改变现有 release Gate：

```powershell
uv run python -m backend.benchmarks.openrca paired-gate `
  --safe-index <runtime-cases.json> `
  --baseline-run-dir <baseline-run-dir> `
  --baseline-evaluation-dir <baseline-evaluation-dir> `
  --candidate-run-dir <candidate-run-dir> `
  --candidate-evaluation-dir <candidate-evaluation-dir> `
  --official-evaluator-root <official-evaluator-git-root> `
  --output <comparison.json>
```

命令只读；`--output` 不得位于 execution 或 evaluation directory 内。safe-index
必须通过现有 strict model 校验；两个 execution bundle 的 fixed predictions 必须
各有 40 个唯一且与 safe-index 完全相同的 case ID；evaluation copy 的 predictions
必须与对应 bundle byte-for-byte 相同。official evaluator root 必须 clean，HEAD
必须与预注册 commit 一致并写入 comparison。

由于 official evaluator CSV 没有 case ID，每个 report 必须各有 40 行和有限
score。paired Gate 从 safe-index 的 `case_id -> instruction` 与对应 frozen fixed
prediction 生成 expected `(query, answer)` multiset：query 只把 CRLF 规范为 LF；
answer 必须解析为 JSON 并以 sorted keys、无多余空白 canonicalize。report 的
`(query, answer)` 使用同一规范并按 multiset（含重复计数）完全相等；不得仅核对
query 或依赖行顺序。

Candidate 必须同时满足：

- candidate evaluation copy 自身通过现有单 run `gate` 的全部阈值；
- 40/40 completed；compatible
  `summary.strategies.fixed.strict_accuracy` 不低于 baseline；
- official partial 使用 40 个原始有限 score 的 `Decimal` 算术平均；candidate 与
  baseline 的差必须 `>= Decimal("0.05")`，不使用显示值或四舍五入值；
- compatible summary 的 component、reason、time 均 `> 0` 且不低于 baseline；
- Evidence reference validity `100%`；projection error/fallback `0/0`；
- read-only violations `0`；deterministic token/cost `0/0`；
- manifest、source、official evaluator 和 artifact checksums 完整。

Paired Gate 产生一个 comparison JSON，至少包含 baseline/candidate run ID、source
SHA、pre-eval manifest SHA、manifest hash、official partial、compatible
strict/component/reason/time、各项差值、基础设施指标、official evaluator SHA、
所有 execution/evaluation artifact SHA 和 pass/fail reasons。Decimal 指标以规范
字符串保存；不得把 compatible partial 冒充 official score，也不得只保存通过结果。

首次 paired Gate 后禁止针对该 holdout 修改规则或重跑来声明改善。通过则进入
最终 reconciliation；失败则归档真实结果、把质量提升 requirement 标记 blocked，
不声称 v10.1 提升了准确率。任何后续算法迭代必须重新冻结未暴露 holdout。

## 10. Error handling, compatibility and safety

1. Counter normalization 不改变 malformed row 的现有 partial/failed 语义。
2. rate 计算拒绝非正 elapsed time 和非有限结果；不产生负 rate Evidence。
3. 新 payload 字段 additive；SQLite/InMemory 历史数据无需 migration，API 和前端
   继续把 payload 当作受限 JSON 显示。
4. Replay 对历史 Evidence 使用 legacy defaults；不得改写冻结 Runtime events、
   attempts、predictions 或 reports。
5. Signal Core 不读取 dataset、task、scenario、Ground Truth、URL 或文件。
6. 生产 Prometheus allowlisted query、read-only mount、Tool registry、安全文案和
   privacy scan 不变。
7. 不增加 dependency、config flag、数据库表、生产写操作或自动执行动作。

## 11. Test strategy and acceptance

### 11.1 Focused contract checks

- Counter：明确累计命名的等速 series 不因绝对水平产生异常；rate 加速可检测；
  单调 memory 等 gauge 不误转；全常量、non-monotonic/reset、重复时间和非有限
  输入保持显式安全行为。
- Degenerate baseline：单点 blip strength 为 presence-only 1；持续零到非零 Evidence
  不丢失；正常 baseline relative strength 不变。
- Ranking：relative/presence 不做 numeric cross-basis 比较；presence 真实信号与
  relative 噪声竞争时按共同 support 决胜；完全同分仍可重复；family coverage
  和 limit 不变。
- Compatibility：历史缺字段 Evidence、SQLite round-trip、Replay、API projection 和
  production acceptance artifact V1/V2 可读；derived legacy 不落盘。
- Holdout：exclusion 生效、重复路径合并、非法 index 拒绝、旧 prepare CLI
  输出不变；execution bundle 不可变；错配 answer/report/evaluator identity、阈值和
  任一独立基础设施条件分别失败。

## 14. Alternatives and decision

### A. Minimal semantic repair — selected

复用现有 adapter、Signal Core、selection 和 Attribution，以 additive Evidence
字段和无权重平局规则修复根因。修改面最小，同时由盲测决定是否真实提分。

### B. Global robust-score redesign — rejected

跨 series 分位数或学习评分需要单位、参数和更大回归面；当前没有证据证明这些
复杂度必要，也更容易拟合已暴露案例。

### C. OpenRCA-only noise filter — rejected

删除零基线单点虽然代码短，但会丢合法瞬时故障并绕过共享语义，只修 benchmark
症状，不满足生产兼容和根因修复要求。
